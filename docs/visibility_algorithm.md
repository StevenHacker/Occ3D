# 3D框可见性计算算法说明

## 核心思想

**问题**：给定一个3D标注框（bbox）和点云，如何量化这个框"被看到多少"？

**解决方案**：在框的表面采样虚拟点，检查每个点是否被遮挡，统计可见比例。

```
                    🚗 目标车辆
                   ┌─────────┐
                   │ ● ● ● ● │ ← 表面采样点
                   │ ● ● ● ● │
                   │ ● ● ● ● │
                   └─────────┘
                        ↑
                        │ 射线
                        │
                   ◉ LiDAR传感器
```

---

## 算法流程

### 步骤1：确定可见面

从传感器位置看，只有朝向传感器的面才可能被看到。

```
俯视图：传感器在bbox左前方

                    +x (后)
                     ↑
            ┌────────┼────────┐
            │        │        │
   -y (左)  │   bbox │        │  +y (右)
     ←──────┼────────┼────────┼──────→
            │        │        │
            │        │        │
            └────────┼────────┘
                     │
                    -x (前)
                     
        ◉ 传感器
      (左前方)

传感器在左前方 → 可见面：前面(-x) + 左面(-y)
```

**只考虑4个侧面**（前后左右），不考虑顶底面，因为：
- 车辆顶面/底面通常不重要
- 减少不必要的计算

### 步骤2：按面积分配采样点

面积大的面分配更多采样点，确保采样密度均匀。

```
示例：一辆车，前面6㎡，侧面12㎡

总采样点 = 60

前面采样 = 60 × (6 / 18) = 20个
侧面采样 = 60 × (12 / 18) = 40个

        ┌─────────────────────────────┐
        │ ●   ●   ●   ●   ●   ●   ●   │
        │                             │   侧面: 40个点
        │ ●   ●   ●   ●   ●   ●   ●   │   (7×6网格≈42个)
        │                             │
        │ ●   ●   ●   ●   ●   ●   ●   │
        └─────────────────────────────┘
                    │
         ┌──────────┴──────────┐
         │  ●    ●    ●    ●   │
         │                     │   前面: 20个点
         │  ●    ●    ●    ●   │   (4×5网格=20个)
         │                     │
         │  ●    ●    ●    ●   │
         └─────────────────────┘
```

### 步骤3：射线遮挡检测

对每个采样点，检查传感器→采样点的射线是否被场景点云遮挡。

```
侧视图：

     采样点 ●──────────────────────────────── ◉ 传感器
              ↖                           ↗
                ↖   射线路径            ↗
                  ↖                   ↗
                    ↖              ↗
                      ╳ 遮挡点云  ↗
                        ↖      ↗
                          ↖ ↗
                           ↗↖
                         ↗    ↖

如果射线路径上有足够多的点 → 判定为"被遮挡"
```

**关键参数**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `ANGLE_THRESH_DEG` | 0.5° | 射线的"宽度"角度 |
| `MIN_BLOCKERS` | 3 | 需要多少个点才算遮挡 |

#### 为什么用角度阈值而不是距离阈值？

```
点云稀疏性：近处密，远处疏

近处（5m）                    远处（50m）
┌─────────────────┐          ┌─────────────────┐
│ ● ● ● ● ● ● ● ● │          │ ●       ●       │
│ ● ● ● ● ● ● ● ● │          │                 │
│ ● ● ● ● ● ● ● ● │          │       ●         │
│ ● ● ● ● ● ● ● ● │          │             ●   │
└─────────────────┘          └─────────────────┘
   点密集                        点稀疏

如果用固定距离阈值（如0.1m）：
  - 近处：正常检测
  - 远处：几乎不可能有点落在射线上 → 误判为"可见"

使用角度阈值：
  - 近处(5m)：射线宽度 = 5m × tan(0.5°) ≈ 0.04m
  - 远处(50m)：射线宽度 = 50m × tan(0.5°) ≈ 0.44m
  
  → 自动适应点云稀疏性！
```

### 步骤4：计算可见性分数

```
可见性 = 未被遮挡的采样点数 / 总采样点数

示例：60个采样点，其中15个被遮挡

可见性 = (60 - 15) / 60 = 75%
```

**分类标准**：

| 状态 | 分数范围 | 含义 |
|------|----------|------|
| VISIBLE | ≥ 70% | 清晰可见 |
| PARTIAL | 30% - 70% | 部分遮挡 |
| OCCLUDED | 5% - 30% | 严重遮挡 |
| BLOCKED | < 5% | 几乎不可见 |

## 为什么要降采样？

### 问题：点云数量巨大

```
典型LiDAR点云：150,000 ~ 300,000 个点
典型bbox数量：10 ~ 50 个
每个bbox采样点：60 个

不降采样的计算量：
  = bbox数 × 采样点数 × 点云数
  = 30 × 60 × 200,000
  = 3.6亿 次距离计算！

时间估计：~10秒/帧 ❌ 完全不可接受
```

### 解决方案：随机降采样

```
降采样前                        降采样后
200,000 个点                    8,000 个点
┌───────────────────────┐      ┌───────────────────────┐
│●●●●●●●●●●●●●●●●●●●●●●│      │●   ●   ●     ●   ●   │
│●●●●●●●●●●●●●●●●●●●●●●│      │    ●       ●   ●     │
│●●●●●●●●●●●●●●●●●●●●●●│  →   │  ●   ●   ●       ●  │
│●●●●●●●●●●●●●●●●●●●●●●│      │●       ●   ●   ●    │
│●●●●●●●●●●●●●●●●●●●●●●│      │  ●   ●       ●   ●  │
└───────────────────────┘      └───────────────────────┘

计算量：30 × 60 × 8,000 = 1440万 次
时间：~200ms/帧 ✓ 可接受
```

### 为什么降采样不影响准确性？

**关键洞察**：我们不需要精确的遮挡边界，只需要知道"有没有东西挡着"。

```
原始点云中的遮挡物：           降采样后：

    ████████████████              ●  ●  ●  ●  ●
    ████████████████      →       ●  ●  ●  ●  ●
    ████████████████              ●  ●  ●  ●  ●

遮挡物仍然存在，只是点变少了。

由于我们用 MIN_BLOCKERS = 3（需要3个点才判定遮挡），
即使降采样后，真正的遮挡物仍会有足够的点落在射线上。
```

**随机采样 vs 均匀采样**：

```
均匀采样（每隔25个取1个）：
原始：A A A A A B B B B B C C C C C ...
采样：A         B         C         ...

问题：如果遮挡物B恰好在采样间隔之间，可能被跳过！

随机采样：
原始：A A A A A B B B B B C C C C C ...
采样：A   A     B   B       C   C   ...

优点：各区域都有概率被采样，不会系统性遗漏任何物体。
```

## 空间过滤（可选优化）

### 思路

不是所有点云都可能造成遮挡，只有在**传感器→bbox方向**上的点才需要检查。

```
俯视图：

                目标bbox
                   ■
                 ↗
               ↗
             ↗ 只检查这个锥形区域内的点
           ↗   
         ↗     
    ◉ ─────────────────────────────────
  传感器
         ↘
           ↘   这些点不可能遮挡目标，跳过！
             ↘
               ↘
                 ↘
                   ↘
```

### 配置

```python
config.SPATIAL_FILTER = True        # 开启
config.SPATIAL_FILTER_ANGLE = 20.0  # 锥形角度 ±20°
```

### 效果

| 场景 | 过滤前点数 | 过滤后点数 | 加速比 |
|------|------------|------------|--------|
| 近处目标(10m) | 150,000 | ~5,000 | 高 |
| 远处目标(50m) | 150,000 | ~30,000 | 中 |

**注意**：对于随机分布的测试数据效果不明显，但对真实LiDAR数据应有明显加速。

## 完整流程图

```
输入: bbox, 点云, 传感器位置
          │
          ▼
    ┌─────────────┐
    │ 1. 解析bbox │ → 中心、尺寸、旋转矩阵
    └──────┬──────┘
           │
           ▼
    ┌─────────────────────┐
    │ 2. 确定可见侧面     │ → 只考虑前后左右4面
    │   (排除顶底面)      │
    └──────┬──────────────┘
           │
           ▼
    ┌─────────────────────┐
    │ 3. 按面积采样       │ → 60个点，均匀分布
    └──────┬──────────────┘
           │
           ▼
    ┌─────────────────────┐
    │ 4. (可选)空间过滤   │ → 只保留相关方向的点
    └──────┬──────────────┘
           │
           ▼
    ┌─────────────────────┐
    │ 5. 降采样点云       │ → 最多8000个点
    └──────┬──────────────┘
           │
           ▼
    ┌─────────────────────┐
    │ 6. 射线遮挡检测     │ → 对每个采样点检查
    │   (角度阈值+最少点) │
    └──────┬──────────────┘
           │
           ▼
    ┌─────────────────────┐
    │ 7. 计算可见性分数   │ → 未遮挡比例
    └──────┬──────────────┘
           │
           ▼
    ┌─────────────────────┐
    │ 8. 分类             │ → VISIBLE/PARTIAL/OCCLUDED/BLOCKED
    └─────────────────────┘
           │
           ▼
输出: 可见性分数 [0,1], 状态
```

## 参数调优指南

| 场景 | 调整 |
|------|------|
| 误判为遮挡（假阴性） | 增大 `ANGLE_THRESH_DEG` 或增大 `MIN_BLOCKERS` |
| 漏判遮挡（假阳性） | 减小 `ANGLE_THRESH_DEG` 或减小 `MIN_BLOCKERS` |
| 速度太慢 | 减小 `TOTAL_SAMPLES` 或 `MAX_SCENE_POINTS` |
| 小目标检测不准 | 增大 `TOTAL_SAMPLES` |
| 远处目标全是BLOCKED | 减小 `ANGLE_THRESH_DEG`（如0.3°） |

## 代码示例

```python
from visibility import compute_visibility, config

# 调整参数
config.TOTAL_SAMPLES = 60
config.ANGLE_THRESH_DEG = 0.5
config.MIN_BLOCKERS = 3
config.MAX_SCENE_POINTS = 8000
config.SIDE_FACES_ONLY = True  # 只考虑侧面

# 计算
score, details = compute_visibility(bbox, points)

print(f"可见性: {score:.0%}")
print(f"状态: {details['status']}")
print(f"采样点: {details['n_samples']}")
print(f"被遮挡: {details['n_blocked']}")
```
